# Selective learning-board revisions

This workflow updates **managed** boards from a completed study build, collection child, prior revision or [selected-object adoption](STUDY-COLLECTIONS.md). Older boards need adoption checkpoints first. Existing low-level edit tools remain available for other boards.

1. Call `goodnotes_prepare_study_revision` with the completed workflow/revision `baseId`, a stable `requestId`, and the new copy title. By default `copy: true` creates a native duplicate, exports both sides, and verifies their text, page dimensions and rendered appearance. Personal additions are included in that duplicate. `copy: false` creates a verified native backup under the requested title and targets the already-authorized original. An optional current `itemPath` supports moved documents; URL and title must still match the original identity.
2. Read the returned stable managed block IDs. `goodnotes_study_revision_status` with `includeContent: true` returns saved text for planning. This is not a fresh read of subsequent manual edits.
3. Call `goodnotes_plan_study_revision` with selected `updates` (block ID, heading, body, page references), bounded `moves` (block ID, new x/y), and/or an `addition`. An addition has its own title/subtitle, figures, cards, column/span settings and sections. It starts below the existing managed board; `appendY` can reserve additional room for personal notes. A new source PDF `sourceExportId` optionally reports changed text/page positions and affected references. Diagram changes with identical text still require visual review. Unchanged blocks retain their earlier source references; supplying a new export does not update their meaning automatically.
4. Review the local preview. It shows managed content only, so also inspect the native board/PDF when personal notes matter. Card updates retain their existing reserved width/height. Longer content must be shortened or added as another card. Changes that overlap managed objects, invalid citations, long moves and swaps through occupied intermediate positions are rejected before writes.
5. Call `goodnotes_run_study_revision` once per step. Each selected existing object must match its saved text, formatting, style and appearance. The visible padding outside the native selection frame is independently compared too. Added content and newly occupied space require visibly empty white space or the native light-gray dot pattern at the fixed workflow zoom. The pattern is independently learned from at least twelve identical tiles across three rows and columns; only matching dot pixels are exempted, not whole cells. Additional marks, other backgrounds and visible notes cause a stop; no background is silently changed. After each write, content is checked after reload and the visible surrounding canvas is compared with the preceding screenshot. Original figures also require the complete native frame, matching aspect/size/position, and identical decoded source pixels with the saved crop (full crop for newly inserted figures). Persisted unselected image screenshots are used for later appearance checks, preserving the separate pre-reload evidence.
6. Inspect the final actual export, then use the completed revision ID as the next `baseId`. Untouched blocks retain their original checkpoints. Changes are not a full rebuild, and no deletion of unrelated objects is performed.

## Recovery

Progress and operation receipts survive restarts. Verified operations are not repeated. Uncertain writes stop; `goodnotes_review_study_revision` can advance only if matching complete block and surroundings evidence exists. A partial change without a checkpoint requires individual inspection. A deliberate repair can be recorded internally only with its own verified operation, a matching new checkpoint, and a successful original surroundings comparison. The original uncertain receipt and original evidence remain unchanged. For a receipt that explicitly proves **no input was sent**, review may allocate a fresh attempt, at most twice, while preserving the rejected receipt and attempt history. The same bounded proof-based recovery applies to preparation copies. Unknown, pending or uncertain copy results cannot trigger another duplication.

## Bounds of the guarantee

- The system protects selected targets and checks visible surroundings. It does not lock remote editing or exhaustively reverify every unchanged object on an infinite board.
- The empty-space check is deliberately conservative and visual. Invisible/hidden objects cannot be certified from pixels.
- Moves must fit within one guarded viewport. Images can be moved; changing an existing image's crop/size is still a separate low-level operation.
- A maximum of 24 card updates, 24 bounded moves, and one added section bundle can be planned per revision. The resulting board height is capped at 12,000 layout pixels. For larger material sets, use the separate [linked collection workflow](STUDY-COLLECTIONS.md).
- Source impact is a text/page-position aid. It is not factual verification or reliable handwriting/diagram change detection.
- Native backup copies improve recovery; PDF comparisons do not prove every hidden native property or iPad delivery.

Private sources, snapshots, before/after images, plans and evidence stay in the runtime directory and must not be published.
